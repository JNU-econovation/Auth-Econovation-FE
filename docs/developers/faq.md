# FAQ / 트러블슈팅

**Q. 콜백은 도착했는데 `code`가 없습니다.**
A. `redirect-url`이 유효성 검증을 통과했는지 확인하세요. `http://` 또는 `https://`로 시작하는 절대 URL이어야 하며, URL 인코딩이 정확해야 합니다.

**Q. 토큰 교환에서 `4010 등록되지 않은 오리진입니다` 에러가 발생합니다.**
A. 다음을 확인하세요.

- 요청을 보내는 서버의 `Origin` 헤더가 등록 오리진과 정확히 일치하는지 (포트 번호 포함)
- 개발 환경에서 호출하고 있다면 개발 오리진이 별도로 등록되어 있는지
- 프록시나 게이트웨이가 `Origin` 헤더를 변경하지 않는지

**Q. 토큰 교환에서 `4012 이미 사용된 임시 토큰` 에러가 발생합니다.**
A. 임시 토큰은 일회용입니다. React `useEffect`가 Strict Mode에서 두 번 실행되거나, 콜백 페이지를 새로고침하면 발생합니다. 교환 시도 결과를 상태(또는 `ref`)로 보관하고 중복 호출을 방지하세요.

**Q. 브라우저에서 직접 토큰 교환 API를 호출해도 되나요?**
A. 권장하지 않습니다. `client_secret`이 클라이언트 코드에 포함되면 누구나 추출할 수 있습니다. 반드시 서버를 거치세요.

**Q. 로컬 개발 환경(`http://localhost:3000`)에서 테스트하려면?**
A. 해당 오리진을 별도로 등록 신청하세요. 등록되지 않은 오리진에서는 토큰 교환이 차단됩니다.

**Q. 한 서비스에 여러 오리진(개발/스테이징/운영)을 등록할 수 있나요?**
A. 가능합니다. 환경별로 별도 등록하세요. *(TBD: 하나의 `client_id`에 여러 오리진을 묶을지, 환경마다 별도 `client_id`를 발급할지는 확정 후 갱신합니다.)*

**Q. 로그인은 성공했는데 "유효하지 않은 리다이렉트 URL입니다" 메시지가 뜹니다.**
A. `redirect-url`이 `http://` 또는 `https://`로 시작하는지, URL 인코딩이 제대로 되었는지 확인하세요. 앱 딥링크 스킴(`your-app://`)은 직접 사용할 수 없으며, 중간 웹 브릿지 페이지가 필요합니다.

**Q. 회원가입 페이지에 `?code=...`를 어떻게 얻나요?**
A. 일반적인 신규 가입에서는 사용하지 않습니다. 기존 회원과 새 인증 수단을 연결하는 흐름(소셜 로그인 연동 등)에서 백엔드/SSO가 발급한 코드를 그대로 전달받아 사용하세요.

**Q. SSO 페이지를 거치지 않고 자체 로그인 UI를 만들어도 되나요?**
A. 본 SSO의 핵심 가치(중앙 인증/세션 일관성)가 사라지므로 권장하지 않습니다. 임시 토큰 교환 방식에서도 SSO 페이지가 인증 UI를 단일하게 제공한다는 점이 보안·UX 측면에서 핵심입니다.

**Q. 토큰의 페이로드(`sub`, `exp`, `role` 등)는 어떻게 구성되나요?**
A. JWT 페이로드 정의는 인증 백엔드 명세를 참고하세요. 본 프론트엔드는 토큰을 그대로 전달만 합니다.
