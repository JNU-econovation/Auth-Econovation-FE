# 운영 런북

운영 중 자주 발생할 수 있는 이슈에 대한 **수동 대응 절차**입니다. 현재 코드베이스에 자동화된 페일오버 / 알림 / 자동 롤백 로직은 포함되어 있지 않으므로, 모든 단계는 운영자가 직접 수행한다고 가정합니다.

## 로그인 실패 급증

**증상**: 회원 여러 명이 동시에 "ID 또는 비밀번호가 일치하지 않습니다" 또는 알 수 없는 에러로 로그인 실패를 보고.

**1차 점검 순서**

1. **백엔드 헬스 체크**: `VITE_API_URL`로 직접 `curl`을 보내 응답을 확인합니다. 본 프론트엔드 문제가 아닌 백엔드 장애일 가능성이 가장 큽니다.
2. **네트워크 탭**: 브라우저 DevTools → Network 탭에서 `POST /api/v1/auth/login` 요청 상태 코드와 응답 바디를 확인합니다.
3. **에러 코드 매핑**: `INVALID_CREDENTIALS` 외의 새로운 `errorCode`가 보이면 [개발자 가이드 — API 명세](../developers/api-reference)에 추가하고 `errorCodeMap.ts`를 갱신합니다.
4. **CORS / withCredentials**: 백엔드 도메인이 변경되었거나 CORS 허용 origin 목록이 갱신되지 않은 경우 로그인이 일제히 실패합니다. 백엔드 운영자에게 확인 요청.

## `VITE_API_URL` 변경이 필요한 경우

`VITE_API_URL`은 **빌드 시점**에 클라이언트 번들에 박혀 들어갑니다. 따라서 변경 후에는 다음 절차가 필요합니다.

1. Vercel 프로젝트의 환경 변수(Production / Preview)에서 값 수정
2. **재배포 트리거** (변경만으로는 반영되지 않음, 새 빌드가 필요)
3. 본 문서의 [개발자 가이드 — 서비스 개요](../developers/) 표에 적힌 URL과 일치하는지 확인

## "유효하지 않은 리다이렉트 URL" 에러 보고

**증상**: 외부 서비스 개발자/사용자가 로그인 후 "유효하지 않은 리다이렉트 URL입니다"를 보고.

**점검**

- `redirect-url` 파라미터가 `http://` 또는 `https://`로 시작하는지
- URL 인코딩이 올바른지 (`encodeURIComponent`)
- 앱 딥링크 스킴(예: `your-app://`)을 직접 사용하지 않았는지 — 현재 검증을 통과하지 않습니다.

**검증 규칙 위치**: 자세한 사양은 [개발자 가이드 — SSO 연동](../developers/sso-integration#redirect-url-검증-규칙).

## 비밀번호 분실 / 계정 복구 문의

현재 시스템에는 **자동 비밀번호 재설정 기능이 없습니다**. 사용자가 비밀번호 분실을 문의해 오면 다음 절차로 대응합니다.

1. 사용자에게 본인 인증 (이름·기수·아이디·연락 수단 등)
2. 백엔드 운영자에게 수동 비밀번호 재설정 / 임시 비밀번호 발급 요청
3. 임시 비밀번호로 로그인 후 변경 안내 → **단, 현재 비밀번호 변경 화면도 본 프론트엔드에는 구현되어 있지 않으므로 백엔드 측 처리가 필요**합니다.
4. 향후 자동화가 필요하면 비밀번호 재설정 흐름을 별도 페이지로 추가하는 것을 검토하세요.

## 토큰 만료 정책 변경

`accessExpiredTime`은 백엔드가 발급하는 초 단위 Unix timestamp입니다. 만료 정책(예: 1시간 → 24시간)을 백엔드에서 변경할 경우:

- 본 프론트엔드 코드 변경은 필요하지 않습니다(값을 그대로 전달만 함).
- 다만 외부 서비스가 만료 처리 로직에 영향을 받을 수 있으니, 연동된 외부 서비스에 변경 사항을 공지하세요.

## 새 외부 서비스가 SSO를 연동하고 싶다고 할 때

1. 운영자가 직접 도와줄 일은 보통 없습니다. [개발자 가이드](../developers/) 링크 전달이 1차 대응입니다.
2. 자주 막히는 부분:
   - `redirect-url`이 절대 URL이 아니거나 인코딩이 빠짐
   - 토큰 교환 요청 시 `Origin` 헤더가 등록 오리진과 불일치 (`4010 등록되지 않은 오리진`)
   - 임시 토큰 재교환 시도 (`4012 이미 사용된 임시 토큰`) — Strict Mode 중복 호출이 흔한 원인
   - `client_secret`이 브라우저에 노출된 상태로 호출 — 반드시 서버 사이드에서만 호출하도록 안내
3. 신규 클라이언트 서비스의 **오리진 등록**이 필요합니다. _(TBD: 등록 신청 절차 확정 시 본 절에 명시)_

## 배포 롤백

Vercel에서는 이전 빌드로 즉시 롤백할 수 있습니다.

1. Vercel 대시보드 → 해당 프로젝트의 **Deployments** 탭
2. 직전 정상 배포 옆 **"…" → Promote to Production**
3. 메인 앱과 문서 사이트는 **다른 Vercel 프로젝트**이므로 각각 별도 롤백이 필요합니다(자세한 분리는 [배포](./deployment)).

## 점검·릴리스 사전 체크리스트

릴리스 PR 머지 전 운영자가 확인해야 할 항목:

- [ ] 로컬에서 `bun run build` 성공
- [ ] 로컬에서 `bun run docs:build` 성공
- [ ] 로컬에서 `bun run test:run` 통과
- [ ] `VITE_API_URL` 변경이 있다면 Vercel 환경 변수 동기화 여부 확인
- [ ] 에러 코드 / 검증 규칙 변경이 있다면 [개발자 가이드](../developers/) 동기화
- [ ] 외부 영향(API URL/도메인/리다이렉트 검증 규칙) 변경 시 동아리 채널 공지
